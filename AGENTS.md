# AGENTS.md

StateWeave TypeScript SDK is a low-level SDK primitive, not a wrapper around AI-engineering frameworks.

- Keep the public agent runtime centered on `immutable causal graph -> bounded working context -> ordinary model action -> causal graph`.
- Expose exactly one public agent class: `Agent`. Do not reintroduce parallel `StateWeaveAgent` or `CausalWeaveAgent` classes. Historical GraphFrame and benchmark runners may remain internal and unexported for frozen evidence.
- Do not expose `messages[]` as a StateWeave primitive. The primary web lab chat runs the public `Agent`; separate historical A/B surfaces may invoke regular messages or the frozen GraphFrame runner for comparison only.
- CLI/manual inspection should accept one user task input, then show compiled causal context, ordinary model actions, tools, and immutable state transitions; graph visualization should stay dependency-free and low-level.
- Provider adapters should be thin HTTP/model primitives.
- Keep Quick Start minimal: `Agent`, `createModelFromEnv`, built-in workspace tools, `getState()`/`getGraph()`, and optional state import. Use `streamEvents()` only for compiled context/action diagnostics. Default `maxIterations` is 30 with no artificial upper cap in SDK/web/server; exhaustion should suggest increasing `maxIterations`.
- `Agent` includes default workspace tools (`read_file`, `write_file`, `edit_file`, `bash_command`); keep them scoped to the configured workspace and visible in run metadata/tool listings. `bash_command` is a read-only command allowlist: do not restore arbitrary shell execution, redirects, pipes, command substitution, network commands, or arbitrary interpreters.

- Challenger review drafts live under `data/challenger-scenarios/*.md`. Each file is one private, multi-turn long-horizon test with scalar frontmatter (`id`, `title`, `tldr`, `domain`, `estimated_turns`, `status`), TL;DR and purpose, a private situation, one headed participant request per declared turn, at least eight hidden acceptance criteria, at least six behavioral checks, a six-or-more-dimension rubric totaling 100, and at least four Challenger notes. - Never read `.env`; it may contain real third-party LLM API keys. Let commands load it without printing it.
- Keep code clean, deliberate, and organized; avoid duplicate helpers, orphan files, and abstraction for its own sake.
- Use minimal comments; prefer clear types and names.
- StateWeave SDK npm promotion: `development` branch publishes `stateweave@dev`, `uat` branch publishes `stateweave@uat`, and `main` publishes `stateweave@latest`. Use GitHub Environments `development`, `uat`, and `production`; do not skip promotion stages unless explicitly approved.
- Architecture thesis: immutable causal graph state replaces provider `messages[]`. Every model action records the exact compiled read set as parents. The runtime—not the model—creates content-addressed lineage for goals, inferences, tool calls/results, resource versions, protocol errors, and answers.
- The complete graph stays append-only. Deterministic projection combines the active frontier, current resource heads, recent evidence, bounded operational closure, lexical relevance, and a whole-graph digest. Supersession affects only projection; it never deletes source nodes.
- `AgentState` import must validate node identity, causal parent ordering, sequence integrity, and frontier references. Stateful calls serialize in invocation order and commit only on success; failed/aborted runs preserve diagnostic state on the error without overwriting committed state.
- `GraphFrame`, `GraphOps`, and `StateGraph` utilities remain low-level exports for graph construction, visualization, and historical artifact compatibility. The public `Agent` does not ask the model to author GraphOps and does not use GraphFrame as its memory engine.
- StateWeave runs should expose metadata and streaming internals: run id/timing/retry counts, tool list, exact compiled prompt, provider metadata such as stop reason/usage when available, output tokens, parsed GraphOps, worker scheduler events, retry errors, and final trace.
- Public `Agent` model output uses ordinary `TOOL_CALL {"name":"...","args":{...}}` or `FINAL:` envelopes. Execute only the first valid action, record its lineage automatically, and expose malformed/unsupported actions as protocol-error nodes. SWX/1 remains internal to the frozen historical GraphFrame runner only.
- Web lab A/B tests must use the same neutral provider system prompt for both regular messages and StateWeave. The shared prompt should explain both variants without favoring either; only the input/state format should differ.
- Web lab prompt eval tabs are blind multi-turn A/B evals: Prompt one has ten connected brand/memory prompts; Prompt two has twenty-five math/physics prompts; Prompt three has thirty harder gold-answer math/logic/physics prompts; Prompt four has 100 auto-judged memory/logical/holistic prompts; Prompt five has 100 balanced adversarial cases across logic-control, distractor, correction, revocation, conflict, entity, order, needle, multihop, and format categories; Prompt six has 300 long-context regression cases across anchor-recall, conflict-latest, revoked-active, order-tracking, and cross-reference categories with live bucket charts and a falsifiable hypothesis. Gold answers are never sent to answer variants. Auto-judged prompts send gold only to two LLM judge calls with distinct system prompts; judge agreement auto-scores unless judge-confirmation is enabled, disagreement pauses for human A/B/both/neither vote. Auto-judged runs execute server-side and persist to `STATEWEAVE_RUN_STORE` (Docker default `/data/eval-runs.json`) so they survive browser refresh/close. Web lab chat/compare traces persist under `STATEWEAVE_TRACE_DIR` (Docker default `/data/traces`).
