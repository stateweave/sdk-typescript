# AGENTS.md

StateWeave TypeScript SDK is a low-level SDK primitive, not a wrapper around AI-engineering frameworks.

- Keep the runtime centered on `GraphFrame -> GraphOps -> StateGraph`.
- Do not expose `messages[]` as a StateWeave primitive. The primary web lab chat is StateWeave-only; a separate A/B testing tab may invoke a regular messages baseline for comparison only.
- CLI/manual inspection should accept one user task input, then show GraphFrame/GraphOps/state transitions clearly; optional graph visualization should stay dependency-free and low-level.
- Provider adapters should be thin HTTP/model primitives.
- Public SDK examples should use `Agent` instead of `StateWeaveAgent`. Keep Quick Start minimal: `Agent`, `createModelFromEnv`, built-in workspace tools, optional `nodeTypes`; use `streamEvents()` only for GraphFrame/GraphOps diagnostics. Default `maxIterations` is 30 with no artificial upper cap in SDK/web/server; exhaustion should surface as a recursion-limit error suggesting increasing `maxIterations`.
- `Agent`/`StateWeaveAgent` includes default workspace tools (`read_file`, `write_file`, `edit_file`, `bash_command`); keep them scoped to the configured workspace and visible in run metadata/tool listings. `bash_command` is a read-only command allowlist: do not restore arbitrary shell execution, redirects, pipes, command substitution, network commands, or arbitrary interpreters.
- The dev lab Infinite tab is the server-owned `InfiniteAgentHarness`: two isolated engineers evolve identical copies of RelayDesk, a live dependency-free Node.js + SQLite + browser full-stack product. Each workspace has the same file tools plus a constrained `app_control` tool for fixed syntax/tests, restart, status, and smoke operations; never weaken this into arbitrary process or network execution. Both live apps are reachable through `/api/infinite-agent/apps/{stateweave,native}/`. Experiment v5 freezes protocol `infinite-v5-blind-matched-20260713`, seed 20260713, an 800-turn stopping rule, and neutral `harbor`/`meadow` workspace names. Both participants receive the exact same neutral provider system, model, ordinary request, tools, verifier, and 300-step budget, with execution order randomized but balanced 4/4 inside every release block; neither prompt may reveal StateWeave/native, candidate/challenger/baseline role, comparison, evaluation, scores, or the other run. Format-specific instructions may explain only the participant's own graph-operation or transcript/tool protocol. The matched transcript challenger summarizes older messages at 250k estimated tokens while retaining twelve, uses an evidence-backed final guard, and gets deliberate long-horizon working-memory guidance. The graph runtime uses compact traces, keeps an append-only graph with preferred (non-whitelist) semantic node types `task`, `file`, `symbol`, `decision`, `constraint`, and `test_result`, and sends a bounded model-facing projection. Both arms must preserve requested mutation/check/restart/smoke evidence; exact route guards and duplicate GET/POST handlers are deterministic gates. Agent/protocol/recursion failures remain scored with zero completion-gated quality; only external provider failures are unscored, and both workspaces plus memory states must roll back before same-turn retry. Randomize arm execution order per request and treat each complete eight-turn full-stack release as the analysis unit; report the seeded block sign-flip permutation p-value, block-bootstrap 95% CI, and exact block sign test, while disclosing that cumulative release blocks are serially dependent and not standalone causal proof. Source seeds must hash identically before turn zero. The harness auto-resumes from `/data/infinite-agent` only when persisted status was idle/running; mismatched protocol versions remain frozen until archive/reset, operator-stopped and failed states remain paused, and Stop aborts then rolls back the active paired turn. Do not deploy harness/runtime/evaluator changes into an active v5 run: stop, archive, bump the protocol/version, and reset instead. Expose live arm/iteration/tool progress plus a heartbeat while a paired turn is running. Completed turns are archived individually, and `/api/infinite-agent/graph` exposes persistent and exact latest model-facing graphs. The Infinite live graph must reuse the Graph memory tab's interactive visualization component (force layout, draggable/pinnable nodes, and inspection), never a separate static renderer.
- Challenger review drafts live under `data/challenger-scenarios/*.md`. Each file is one private, multi-turn long-horizon test with scalar frontmatter (`id`, `title`, `tldr`, `domain`, `estimated_turns`, `status`), TL;DR and purpose, a private situation, one headed participant request per declared turn, at least eight hidden acceptance criteria, at least six behavioral checks, a six-or-more-dimension rubric totaling 100, and at least four Challenger notes. Corpus tests require at least 600 body words per scenario in addition to enforcing unique ids, 24 files, 180 turns, and 3x8 domain balance. The read-only `/api/infinite-agent/scenarios` library and Infinite-tab Markdown reader are for human review; do not expose the private files to participant tools or wire drafts into a scored protocol without a new frozen experiment version.
- Never read `.env`; it may contain real third-party LLM API keys. Let commands load it without printing it.
- Keep code clean, deliberate, and organized; avoid duplicate helpers, orphan files, and abstraction for its own sake.
- Use minimal comments; prefer clear types and names.
- StateWeave SDK npm promotion: `development` branch publishes `stateweave@dev`, `uat` branch publishes `stateweave@uat`, and `main` publishes `stateweave@latest`. Use GitHub Environments `development`, `uat`, and `production`; do not skip promotion stages unless explicitly approved.
- Architecture thesis: StateGraph replaces provider `messages[]`. The graph starts from a system/root node, can later add system nodes anywhere, and the root can point/follow the active system node. Each model call receives a compiled GraphFrame/subgraph view, not messages; GraphOps grow/traverse the graph intelligently and may eventually run async/parallel over multiple graph regions.
- Cortex model: keep `system_root` as the center but do not hard-code branch/continuation attachment. New `user_input_N` nodes enter as pending inputs; the model must return GraphOps edges deciding whether they start from `system_root`, continue a prior user/assistant node, update an output/semantic node, or relate elsewhere. Do not add a separate `branch` node type or `branchId` metadata. Carry `focusNodeId`, `activeUserInputNodeId`, and `candidateFocusNodeIds` in GraphFrame. Structural node types are only `system`, `user_input`, `assistant_output`, `tool_call`, and `tool_result`; every other node type is a model-created semantic slug, including artifact-like outputs.
- GraphOps are transactional SDK mutations: after apply, the latest pending `user_input_N` and every new semantic/output node must be connected to the existing graph. Reject invalid/disconnected GraphOps and retry with structured `lastGraphOpsError`; do not silently leave orphan nodes floating.
- StateWeave runs should expose metadata and streaming internals: run id/timing/retry counts, tool list, exact compiled prompt, provider metadata such as stop reason/usage when available, output tokens, parsed GraphOps, worker scheduler events, retry errors, and final trace.
- Model graph output should use SWX/1 (StateWeave Exchange): compact `@node`/`@edge`/`@worker`/`@final`/`@final_ref` line commands plus raw `<<<artifact:mime ... >>>` blocks for SVG/HTML/code/artifacts and long final answers. `@worker` spawns built-in graph workers on focused regions; do not combine `@worker` with `@final` in one transaction. Final answers must be human-readable text; artifact ids belong in `artifact=`/`artifacts=` refs, not as the whole answer.
- Web lab A/B tests must use the same neutral provider system prompt for both regular messages and StateWeave. The shared prompt should explain both variants without favoring either; only the input/state format should differ.
- Web lab prompt eval tabs are blind multi-turn A/B evals: Prompt one has ten connected brand/memory prompts; Prompt two has twenty-five math/physics prompts; Prompt three has thirty harder gold-answer math/logic/physics prompts; Prompt four has 100 auto-judged memory/logical/holistic prompts; Prompt five has 100 balanced adversarial cases across logic-control, distractor, correction, revocation, conflict, entity, order, needle, multihop, and format categories; Prompt six has 300 long-context regression cases across anchor-recall, conflict-latest, revoked-active, order-tracking, and cross-reference categories with live bucket charts and a falsifiable hypothesis. Gold answers are never sent to answer variants. Auto-judged prompts send gold only to two LLM judge calls with distinct system prompts; judge agreement auto-scores unless judge-confirmation is enabled, disagreement pauses for human A/B/both/neither vote. Auto-judged runs execute server-side and persist to `STATEWEAVE_RUN_STORE` (Docker default `/data/eval-runs.json`) so they survive browser refresh/close. Web lab chat/compare traces persist under `STATEWEAVE_TRACE_DIR` (Docker default `/data/traces`).
